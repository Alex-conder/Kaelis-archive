# A11: 开发路线与里程碑建议 (Roadmap & Milestones)

> 基于 A0-A10 盘点结果，制定从当前状态到可用产品的开发路线。

## 1. 当前状态总结

| 维度 | 评分 | 说明 |
|------|------|------|
| 后端引擎 | 🟢 9/10 | 记忆、自进化、MCP、多组学均成熟 |
| API 层 | 🟢 8/10 | 350+ 端点，功能完整 |
| 测试覆盖 | 🟢 7/10 | 612 tests，75%+ 覆盖率 |
| Electron 壳 | 🟢 7/10 | 主进程成熟，打包配置完整 |
| **前端功能** | 🔴 **2/10** | **仅骨架，产品不可用** |
| MCP 测试 | 🔴 3/10 | 覆盖率洼地 |
| CI 稳定性 | 🟡 5/10 | ChromaDB 网络问题 |

## 2. 开发路线

### Phase 0: 基础加固（第 1-2 周）

**目标**：消除阻塞项，确保开发环境稳定

| 任务 | 工作量 | 交付物 |
|------|--------|--------|
| 补充 MCP Server/Client 测试至 75%+ | 4-5 天 | `test_mcp_server.py` / `test_mcp_client.py` 扩展 |
| Mock ChromaDB ONNX 下载 | 1-2 天 | CI 稳定性提升 |
| 前端项目结构初始化 | 2-3 天 | React Router + API 客户端 + 错误边界 |
| 技术债务清理（TODO 分析） | 1-2 天 | 债务优先级清单 |

**里程碑**：CI 全绿 + 前端开发环境就绪

### Phase 1: 前端 MVP（第 3-6 周）

**目标**：用户可与 Agent 进行基本对话

| 任务 | 工作量 | 交付物 |
|------|--------|--------|
| 认证流程 UI（登录/注册/退出） | 3-4 天 | Auth 页面 + Zustand store 对接 |
| 核心聊天界面 | 7-10 天 | 对话流、Markdown 渲染、代码高亮 |
| API 客户端层 | 3-4 天 | axios 封装、错误处理、加载状态 |
| 全局状态管理 | 2-3 天 | Zustand store 分层（auth/chat/memory） |
| 基本路由 | 1-2 天 | /login /chat /settings |

**里程碑**：Electron 打包后可运行，用户能发送消息并收到回复

### Phase 2: 功能完整（第 7-12 周）

**目标**：核心功能可通过 UI 访问

| 任务 | 工作量 | 交付物 |
|------|--------|--------|
| 记忆浏览器 | 5-7 天 | L0-L3 列表、搜索、详情 |
| 技能市场 UI | 5-7 天 | 技能列表、安装、详情页 |
| 设置面板 | 3-4 天 | 用户偏好、LLM 配置、主题 |
| 系统状态面板 | 3-4 天 | Agent 健康度、指标可视化 |
| 前端测试引入 | 3-5 天 | Vitest 已配置 (Playwright 尚未配置) 基础套件 |

**里程碑**：所有后端功能有对应 UI，产品可用

### Phase 3: 体验优化（第 13-18 周）

**目标**：产品体验达到竞品水平

| 任务 | 工作量 | 交付物 |
|------|--------|--------|
| LLM 流式输出 | 3-5 天 | SSE 流式响应、打字机效果 |
| 进化过程可视化 | 5-7 天 | 策略选择轨迹、优化曲线 |
| 记忆图谱可视化 | 5-7 天 | 语义网络图谱（ECharts/D3） |
| 工作流可视化 | 5-7 天 | 多组学工作流 DAG 图 |
| 设计系统统一 | 5-7 天 | 组件库、主题系统、动画 |

**里程碑**：用户体验与 Hermes/OpenClaw 相当

### Phase 4: 平台扩展（第 19-26 周）

**目标**：多平台、开源、生态建设

| 任务 | 工作量 | 交付物 |
|------|--------|--------|
| VSCode Extension 原型 | 4-6 周 | Chat Provider + MCP 桥接 |
| 后端 MCP Server 抽象 | 2-3 周 | 标准化 MCP 接口 |
| 开源准备 | 2-3 周 | LICENSE、CONTRIBUTING、文档 |
| 社区建设 | 持续 | README、Demo、博客 |
| PostgreSQL 支持评估 | 2-3 周 | 可选 PostgreSQL 后端 |

**里程碑**：进入 VSCode 生态 + 开源社区启动

## 3. 里程碑检查点

| 里程碑 | 时间 | 成功标准 |
|--------|------|----------|
| **M0: 环境就绪** | Week 2 | CI 100% 通过，前端 dev server 可启动 |
| **M1: 对话可用** | Week 6 | 用户可发送消息，Agent 可回复，Electron 可打包 |
| **M2: 功能完整** | Week 12 | 记忆/技能/设置/状态均有 UI，无 404 功能 |
| **M3: 体验达标** | Week 18 | 流式输出、可视化、设计系统完成 |
| **M4: 生态启动** | Week 26 | VSCode Extension MVP + GitHub 开源 |

## 5. 风险缓解

| 风险 | 缓解措施 |
|------|----------|
| 前端开发进度延迟 | 优先完成聊天界面，其他功能可延后 |
| 后端 API 变更导致前端返工 | 定义 OpenAPI/Swagger 契约，前端 mock 开发 |
| Electron 打包问题 | 每两周执行一次完整打包验证 |
| 竞品加速 | 聚焦多组学差异化，避免正面竞争 |
