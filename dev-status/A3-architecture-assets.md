## 2. 通信模式

| 通道 | 协议 | 用途 | 状态 |
|------|------|------|------|
| Electron ↔ Flask | HTTP (localhost:5000) | API 调用 | ✅ 成熟 |
| Electron ↔ Renderer | IPC (preload.cjs) | 安全桥接 | ✅ 存在 |
| Flask ↔ SQLite | SQL (db_pool.py) | 主数据持久化 | ✅ 成熟 |
| Flask ↔ ChromaDB | Chroma Client | 向量检索 | ✅ 已迁移到 PersistentClient |
| Flask ↔ MCP Server | stdio / SSE | 外部工具集成 | ✅ 双模式 |
| MCP Client ↔ 外部 | stdio / SSE | 第三方 MCP 服务 | ✅ 已集成 |

## 3. 部署架构

### 3.1 开发模式
```
npm run electron:dev  →  Electron 加载 dev server (Vite HMR)
                        →  Flask 以子进程启动 (Python 3.14)
```

### 3.2 生产模式
```
electron-builder 打包  →  ASAR 压缩前端
                        →  嵌入 Python 3.11 runtime (resources/python/)
                        →  打包 api/ + core/ + launch.py
                        →  NSIS / DMG / AppImage 安装包
```

## 4. 关键架构决策

| 决策 | 选择 | 评估 |
|------|------|------|
| 桌面框架 | Electron (非 Tauri) | 成熟但包体积大 (~200MB+) |
| 前后端通信 | HTTP (非 gRPC/WebSocket) | 简单但实时性受限 |
| 数据库 | SQLite (非 PostgreSQL) | 零配置但并发受限 |
| 向量存储 | ChromaDB + FAISS | 双保险但维护成本高 |
| Python Runtime | 嵌入式 3.11 | 自包含但更新困难 |
| 打包 | electron-builder | 成熟，支持多平台 |

## 5. 架构健康度

| 维度 | 评分 | 说明 |
|------|------|------|
| 分层清晰度 | 🟢 8/10 | core/api 分离良好 |
| 依赖方向 | 🟢 7/10 | 基本遵循内层不依赖外层 |
| 可测试性 | 🟢 7/10 | pytest 覆盖 75%+ |
| 可扩展性 | 🟡 6/10 | 新增 API 路由简单，但 core 模块耦合需关注 |
| 可部署性 | 🟡 6/10 | Electron 打包复杂，嵌入式 Python 体积大 |
| 实时通信 | 🔴 3/10 | 无 WebSocket，前端轮询或 HTTP 长轮询 |

## 6. 架构风险

1. **HTTP 瓶颈**：所有前后端通信走 HTTP，无 WebSocket/Server-Sent Events，实时推送（如主动记忆）需要轮询
2. **SQLite 并发**：多用户场景下 SQLite 写锁会成为瓶颈
3. **嵌入式 Python 更新**：`resources/python/` 中的 Python 3.11 runtime 难以热更新
4. **包体积**：嵌入式 Python + 模型文件可能导致安装包 >500MB
5. **无微服务拆分**：单体 Flask 应用，长期扩展受限
