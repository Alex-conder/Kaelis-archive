# Kaelis 团队记忆共享 GDPR 补充条款

> **文档版本**: 1.0  
> **生效日期**: 2026-04-29  
> **适用范围**: Agent 团队功能（D-5 及后续团队编排模块）

---

## 1. 团队记忆共享的数据责任模型

当 Kaelis 进入**多 Agent 团队编排**阶段时，记忆数据将在团队成员之间产生流动。本文件明确各角色对共享记忆的数据权利与责任边界。

### 1.1 数据分类

| 数据类型 | 定义 | 存储位置 | 责任主体 |
|----------|------|----------|----------|
| **个人记忆** | 单个用户/Agent 独立产生的 L1/L2 记录 | `memory_l1`/`memory_l2` (user_id 隔离) | 个人用户 |
| **团队共享记忆** | 经成员授权后汇入团队知识池的 L3 实体和关系 | `kg_entities`/`kg_relations` (team_id 标记) | 团队管理员 |
| **协作痕迹** | 团队对话、决策日志、共识记录 | `shared_memory` 表 | 团队全体成员 |

### 1.2 角色定义

| 角色 | 权限 | 数据责任 |
|------|------|----------|
| **团队创建者 (Owner)** | 完全控制：添加/移除成员、导出全部数据、解散团队 | 对团队全部数据负最终责任 |
| **团队管理员 (Admin)** | 管理：审批记忆共享请求、导出团队数据、配置保留策略 | 对团队数据合规性负责 |
| **普通成员 (Member)** | 贡献：授权个人记忆汇入团队池、查看共享记忆、导出个人贡献 | 仅对个人授权数据负责 |
| **访客 (Guest)** | 只读：查看被授权的共享记忆片段 | 无数据管理责任 |

## 2. 用户权利（团队场景扩展）

### 2.1 被遗忘权在团队中的执行

**个人退出团队时**：
- 用户可要求删除其在团队中的**个人记忆副本**
- 团队共享池中由该用户贡献的**知识图谱实体**将匿名化处理（保留语义价值，去除 user_id 关联）
- 协作痕迹（如会议纪要）中涉及该用户的引用保留，但显示为 "[已退出成员]"

**团队解散时**：
- 团队创建者可选择：
  - **完全删除**: 所有团队共享记忆物理删除
  - **个人回收**: 各成员可选择将团队池中自己贡献的部分回收至个人账户
  - **归档导出**: 导出为 JSON 归档文件，供团队创建者留存

### 2.2 数据可携带权（团队场景）

| 角色 | 可导出范围 | 格式 |
|------|------------|------|
| 团队创建者 | 全部团队数据（含成员贡献） | JSON / CSV |
| 团队管理员 | 全部团队数据 | JSON / CSV |
| 普通成员 | 仅个人贡献部分 + 公开共享记忆 | JSON |

**导出内容示例**:
```json
{
  "export_type": "team_partial",
  "team_id": "team_abc123",
  "user_id": "user_xyz789",
  "exported_at": "2026-04-29T12:00:00Z",
  "personal_contributions": {
    "kg_entities": [...],
    "shared_memories": [...]
  },
  "shared_pool_accessible": {
    "public_entities": [...]
  }
}
```

### 2.3 知情权与同意

**记忆汇入团队池前**：
- 系统必须弹窗提示用户："您即将将 [X] 条个人记忆汇入团队共享池。汇入后，团队管理员可查看这些记忆的语义摘要，但无法查看原始隐私内容。"
- 用户可选择：
  - ✅ **完全授权**: 汇入全部内容
  - ⚠️ **摘要授权**: 仅汇入关键词和主题标签（TF-IDF 提取），不汇入原始文本
  - ❌ **拒绝**: 不汇入

**记忆敏感度分级**:
- **公开 (Public)**: 团队所有成员可见，可导出
- **受限 (Restricted)**: 仅管理员和创建者可见
- **私有 (Private)**: 仅贡献者本人可见，即使汇入团队池也保持 user_id 加密

## 3. API 扩展（团队隐私控制）

### 3.1 团队数据导出

```http
GET /api/teams/{team_id}/privacy/export
Authorization: Bearer <team_admin_token>

Query Parameters:
  - scope: "full" | "personal" | "public"
  - format: "json" | "csv"
  - anonymize: true | false  (是否去除 user_id)
```

### 3.2 团队成员被遗忘权

```http
POST /api/teams/{team_id}/privacy/leave
Authorization: Bearer <user_token>

Request Body:
{
  "delete_personal_copies": true,
  "anonymize_contributions": true,
  "export_before_leave": true
}
```

### 3.3 团队解散

```http
POST /api/teams/{team_id}/privacy/dissolve
Authorization: Bearer <team_owner_token>

Request Body:
{
  "action": "delete_all" | "personal_recovery" | "archive",
  "archive_email": "owner@example.com"  (若选择 archive)
}
```

## 4. 合规检查清单

在部署团队功能前，必须完成以下检查：

- [ ] 团队创建流程中包含隐私协议确认步骤
- [ ] 记忆汇入团队池前强制显示同意弹窗
- [ ] 团队设置页面提供"数据保留期限"配置（30/90/365 天）
- [ ] 团队成员列表页面显示每个人的数据贡献量和导出权限
- [ ] 团队解散时发送邮件确认（72 小时延迟执行）
- [ ] 审计日志记录所有团队级数据导出/删除/匿名化操作
- [ ] 为团队数据提供独立的 SQLite 数据库文件（便于物理隔离和导出）

## 5. 与基础 GDPR 框架的关系

本文档是 `docs/GDPR_COMPLIANCE.md` 的**补充条款**，而非替代。

- **基础框架** (`GDPR_COMPLIANCE.md`): 适用于个人用户的全部权利
- **团队补充** (`GDPR_TEAMS.md`): 仅适用于多用户协作场景下的权利边界

当两者冲突时，**更严格的条款优先**。例如：
- 基础框架允许用户导出全部数据
- 团队补充限制普通成员仅能导出个人贡献
- **执行标准**: 普通成员在团队场景中受团队补充限制，但退出团队后恢复完整个人权利

## 6. 示例场景

### 场景 A: 用户 A 退出团队
1. A 点击"退出团队"
2. 系统提示："退出后，您在团队中的个人记忆副本将被删除。您贡献的知识图谱实体将被匿名化。是否先导出您的个人贡献？"
3. A 选择"导出并退出"
4. 系统生成 JSON 文件，删除 A 的 user_id 关联，匿名化 L3 实体
5. A 收到确认邮件

### 场景 B: 团队管理员导出数据
1. 管理员请求导出团队全部数据
2. 系统向所有成员发送通知："管理员 [Name] 请求导出团队数据。如无异议，将在 24 小时后执行。"
3. 若有成员异议，导出请求被拒绝
4. 若无异议，生成加密 ZIP 文件，仅管理员可下载，7 天后自动删除

### 场景 C: 团队解散
1. 创建者发起解散
2. 系统进入 72 小时冷静期，期间可取消
3. 冷静期结束后，各成员收到通知："团队即将解散，请选择数据处理方式：回收至个人账户 / 允许归档 / 放弃"
4. 根据各成员选择执行相应操作
